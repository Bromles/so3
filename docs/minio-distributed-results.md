# Результаты k6 S3 benchmark: MinIO distributed

Последняя локальная проверка k6: 2026-05-17 на macOS, один физический хост c M4 Pro.

## Команда

```bash
BACKEND_START_TIMEOUT_SECS=120 python scripts/k6/run-backend-benchmark.py --backend minio-distributed --runs 30 --outdir /tmp/minio-distributed-k6-clean-30-json
```

## Методика

Backend: `quay.io/minio/minio:latest`, RELEASE.2025-09-07T16-13-09Z (go1.24.6 linux/arm64).
Режим: 4 контейнера MinIO в distributed erasure-set configuration, S3 endpoint опубликован через первый контейнер.
Конфигурация k6: 10 VU, 30 запусков по 30 секунд, объекты по 64 байта. Каждая итерация выполняет S3-операции
`putObject -> getObject -> HEAD Object -> deleteObject`.
`putObject`, `getObject` и `deleteObject` вызываются через k6 S3Client. `HEAD Object` выполняется прямым HTTP `HEAD`,
подписанным SigV4 для совместимости с приватными bucket.

Каждый k6-запуск был чистым: runner перед каждым прогоном запускал новый Docker Compose с новой временной
директорией данных, после прогона останавливал контейнеры и делал очистку.

Статистика ниже рассчитана по 30 независимым запускам. `σ` — стандартное отклонение, `стандартная ошибка` и `95% ДИ` —
оценки неопределённости среднего; `коэф. вариации` — относительный разброс. Дисперсия считается как выборочная (`n - 1`
в знаменателе).
