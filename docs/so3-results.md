# Результаты k6 baseline: so3

Этот отчет фиксирует исторический исходный уровень самого прототипа. Абсолютные значения пропускной способности и
задержек не являются продуктовым заявлением и не используются для сравнения с промышленными S3-совместимыми системами.
Основное назначение этих данных — воспроизводимость и дальнейшая нормализация сценариев с отказами, конфликтами
и восстановлением.

Последняя локальная проверка k6: 2026-05-17 на macOS, один физический хост c M4 Pro.

## Команда

```bash
uv run python scripts/k6/run-backend-benchmark.py --backend so3 --runs 30 --outdir /tmp/so3-k6-backend-clean-30-json
```

Бинарный файл: `target/release/so3`.
Конфигурация: 10 VU, 30 запусков по 30 секунд, объекты по 64 байта. Каждая итерация выполняет
S3-операции `putObject -> getObject -> HEAD Object -> deleteObject`: `putObject`, `getObject` и
`deleteObject` вызываются через k6 S3Client, а `HEAD Object` выполняется прямым HTTP `HEAD` к
S3-совместимому endpoint, потому что в используемом клиенте нет отдельного `headObject`.

Каждый k6-запуск был чистым: `scripts/k6/run-backend-benchmark.py --backend so3` перед каждым
прогоном запускал новый release-процесс `so3` с новой временной `SO3_DATA_DIR=/tmp/so3-k6-run-*`,
после прогона останавливал процесс и удалял директорию данных. Поэтому агрегаты ниже не включают
накопленные данные и фоновые накладные расходы от предыдущих прогонов.

Статистика ниже рассчитана по 30 независимым запускам. `σ` — стандартное отклонение,
`стандартная ошибка` и `95% ДИ` — оценки неопределённости среднего; `коэф. вариации` —
коэффициент вариации, то есть относительный разброс. Дисперсия считается как выборочная
(`n - 1` в знаменателе); `95% ДИ` использует t-критическое значение для 29 степеней свободы.
Для метрик задержки агрегируются значения, которые k6 посчитал внутри каждого отдельного запуска.
